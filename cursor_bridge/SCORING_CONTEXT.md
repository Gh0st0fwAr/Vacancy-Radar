# Контекст скоринга для Cursor SDK и IDE (без жёстких Python-формул)

Задача Cursor: оценить FIT вакансии к кандидату **по смыслу**, опираясь на переданный контекст.
Не копируй балльную схему `radar/scorer.py` (+20 remote, +25 Vue и т.п.). Скоринг — твоё суждение по профилю.

## Обязательный контекст кандидата

1. Блок **CANDIDATE** в payload — главный источник правды: полный текст резюме (загруженного пользователем), опционально портфолио и GitHub из того же блока.
2. Если блок CANDIDATE пуст или отсутствует — **score=0, accept=false**, без догадок и без выдуманного профиля.
3. Портфолио и GitHub учитывай только если они явно переданы в payload; отсутствие ссылок не отменяет скоринг по тексту резюме.
4. Не клонируй исходники портфолио как proof of skill. Не отказывай в скоре, если URL недоступны онлайн — текст резюме и ссылки уже в контексте.

## Якорь — шапка и уровень из резюме

Ориентируйся на **фактическую шапку резюме** в блоке CANDIDATE (роль, стек, грейд).

- Совпадение роли/стека вакансии с шапкой резюме — плюс к FIT.
- Несовпадение грейда: **Senior/Lead в заголовке вакансии = минус 8–12, не ноль**, если ядро стека совпадает с профилем.
- Стеки, которых нет в резюме как сильная сторона, — минус; отсутствие второстепенного требования не штрафуй.

## Ориентиры профиля (не формулы)

- Оценивай честно: сильные стороны из резюме и портфолио, слабые — без завышения.
- Предпочтения (формат работы, зарплата, локация) бери из текста профиля и блоков **PREFERENCES** / **KEYWORDS**, если Python их передал.
- Не подставляй чужие предпочтения, если их нет в payload.

## Калибровка accept (порог очереди)

`accept=true` только при genuine FIT, обычно score ≥ порога очереди. Не поднимай score «чтобы прошло».

- Честный FIT ниже порога → `accept=false`, даже если ключевые слова совпали.
- Не раздувай score до threshold без реального соответствия профилю.

## Блоки от Python (приоритет)

Если в payload есть блоки **KEYWORDS** (Reject / Desirable / Must / Nice) или **VACANCY REFERENCES** — они важнее мягкой калибровки:

- **Reject / Must-not** — сильный минус или `accept=false`, даже если стек в целом близок.
- **Desirable / Must** — усиливают FIT, если подтверждаются резюме.
- **Vacancy references** (похожие прошлые вакансии) — только **позитивные** сигналы; не копируй их score буквально.

## Ответ

Только JSON: `{"score":0-100,"accept":true|false,"reasons":["…"]}`

`reasons`: 2–6 коротких пунктов, почему fit / не fit.

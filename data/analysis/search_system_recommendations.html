Как искать жёстко по роли, но не резать хорошие вакансии

Документ для спокойного чтения. Опирается на прогон дизайнера (20:34–20:53, ~18.5 мин, deep 254 → Cursor 124 → в очередь 1) и на текущую архитектуру: dual SERP, Reject, sphere_filter, Cursor SDK. Цель: жизнеспособная картина — быстро отсекать мусор, оставлять спорные, но правдоподобные FIT.

1. Диагноз

Система сейчас умеет говорить «это явно плохо» только в узких случаях (golang для дизайнера, «менеджер по продажам» как целая фраза). Она почти не умеет говорить «это обязано быть ролью сферы». Поэтому HH спокойно приносит врачей, колл-центры, ML-инженеров и менеджеров WB — а Cursor через минуты честно ставит 0–8%.

Главный вывод прогона: Cursor в целом прав по низким скорам, но работает как дорогой финальный судья на потоке, который не должен был до него доходить. Из ~254 deep только ~124 дошли до SDK; из них ≤35% — порядка 115. Хорошие дизайн-роли в топе были (карточки, digital, арт-директор e-com), но утонули в шуме.

Четыре конкретные дыры

  1. Dual SERP слишком щедрый. Primary = sphere seeds (ок), secondary = Desirable OR по name+description. Слова вроде «маркетплейс», «Ozon», «Figma», «Москва», «гибрид» — не роль. Они тянут логистов, менеджеров, маркетологов.
  2. Sphere = thin blacklist, не allowlist. «Врач-неонатолог» и «Оператор call-центра» легальны для текущего designer-гейта.
  3. Reject слишком литературный. Есть «менеджер по продажам», нет политики «менеджер без design-сигнала». «Руководитель команды разработки» не матчит reject «разработчик» (другая словоформа).
  4. Preferences смешивают ортогональные оси. В одном Desirable лежат роль (инфографика), инструмент (Photoshop), формат (гибрид), гео (Москва), деньги (115000). Для SERP это яд; для Cursor — терпимо.
Хорошая новость: чинить нужно не «магией Cursor», а дешёвым prefilter по заголовку + более честной семантикой seeds. Cursor оставить для пограничных дизайн-ролей (3D / motion / UI-only / арт-директор), где Python не должен рубить топором.

2. Принцип: три слоя уверенности

Чтобы не резать хорошее, каждый фильтр должен иметь явную уверенность. Неясное — не kill, а «дорогому судье».

Слой A — Hard kill (бесплатно) Очевидный мусор по title: врач, курьер, бухгалтер, call-центр, «менеджер по продажам», golang/devops без design-слова. Ошибка здесь дорогая → паттерны только высокоточные.
Слой B — Soft require (почти бесплатно) Для известной сферы: в title (или коротком SERP snippet) должен быть ролевой сигнал сферы. Нет сигнала → не deep/Cursor. Исключения — короткий whitelist редких формулировок.
Слой C — Cursor judge (дорого) Только карточки, прошедшие A+B. Здесь решаем FIT: карточки WB vs чистый UI/UX, грейд, деньги, гибрид, портфолио.
Слой D — Preferences как оси, не каша Role keywords ≠ tools ≠ work format ≠ geo ≠ salary. В SERP участвует только role (+ осторожно tools). Format/geo/salary — в Cursor / soft score, не в HH text=.
Золотое правило: лучше пропустить спорный «Дизайнер презентаций» в Cursor, чем убить его на title-гейте. Лучше убить «Логист Wildberries» на title, чем отдавать в SDK.

3. Целевая воронка

1
Seed A — Role SERP (обязательный) URL из Activity sphere: дизайнер OR designer OR графический дизайнер OR иллюстратор + при желании узкие role-синонимы профиля («дизайнер карточек», «инфографика» как роль). search_field=name предпочтителен; description — только если мало выдачи.
2
Seed B — Optional boost (не обязан) Отдельный OR только из role-desirable (не Москва/гибрид/зарплата). Можно выключать тогглом «Desirable SERP». По умолчанию для шумных сфер — off или name-only.
3
Primary card gate (до chrome deep) Reject keywords (улучшенные) → sphere hard-kill → sphere allowlist title. Здесь должна умирать основная масса мусора.
4
Deep fetch + secondary gate Полный текст только для прошедших title. Secondary reject/sphere на тексте — ловит «в тексте вакансии сплошные продажи», если title был маскирующий.
5
Cursor SDK FIT к резюме/портфолио + prefs axes + references. Не «является ли это работой вообще».
Ожидаемый эффект на похожем Clear Check: deep не 254, а условно 40–80; Cursor не 124, а 30–60; доля ≤10% резко падает; время с ~18 мин к нескольким. Точные цифры — после A/B на том же search_period.

4. Перестройка SERP

4.1 Primary URL = только роль сферы

То, что уже сделано (sphere → hh_search_url), — правильное направление. Усилить:

  • Для designer seeds добавить аккуратные синонимы роли: дизайнер карточек, инфографика (как role), graphic designer, коммуникационный дизайнер — но не Ozon/WB как отдельные OR без слова «дизайн».
  • Параметр: search_field=name для primary. Description включать только если за N страниц мало карточек (адаптивный fallback).
  • Не смешивать schedule=remote как единственный догмат для дизайна: у кандидата в prefs был гибрид. Лучше вынести format в отдельный конфиг-флаг: remote / remote+hybrid / any, и крутить HH schedule/фильтры осознанно.

4.2 Desirable SERP — сделать безопасным или выключить

Тип токенаВ Desirable UIВ HH text=Почему
Роль: «дизайнер карточек», «инфографика» дада (осторожно) усиливает role seed
Инструмент: Figma, Photoshop далучше нет / только name Figma есть у менеджеров продукта и маркетологов
Площадка: WB, Ozon, маркетплейс нейтраль/контекстнет тянет логистов и менеджеров МП
Формат: удалёнка, гибрид отдельная осьнет (есть schedule) не роль
Гео / ЗП: Москва, 115000 отдельная осьнет максимальный шум в description
Практично в коде: помечать bucket-теги типами (role / tool / context / format / comp) или завести рядом с Desirable поле «SERP keywords» (явный список для HH), а Desirable оставить для Cursor boost.

4.3 Альтернатива dual-seed

  • Вариант «один чистый seed» — только sphere role URL. Проще, меньше шума. Риск: меньше охват редких формулировок.
  • Вариант «два seed, оба role» — sphere URL + URL из role-desirable only.
  • Вариант «sphere + negative HH» — если HH API/UI позволит исключать слова в поиске (не всегда стабильно) — не строить на этом основу.

5. Title-гейт: allowlist + умный blacklist

5.1 Allowlist (слой B) — сердце ускорения

Если Activity sphere нормализуется в designer, карточка идёт в deep только если title/snippet содержит хотя бы один сигнал:

дизайнер designer illustrator иллюстратор инфографик арт-директор art director графическ коммуникационный дизайнер motion design ui/ux product designer figma (слабый — лучше как secondary signal)

Figma / Photoshop в title без «дизайн» — слабый сигнал. Можно считать allow только в паре с role-словом, либо пускать в «серую зону» с лимитом.

5.2 Исключения allowlist (чтобы не резать хорошее)

  • Creative / Brand / Visual без слова «дизайн», но с явным creative-role: «Brand Designer», «Visual Designer», «Digital Designer» — уже покрыто designer.
  • Арт-директор / Art Director — иногда без «дизайн» в title; держать в allow.
  • Редкие RU-формулировки: «Художник-оформитель», «Дизайнер-верстальщик» (верстальщик спорный — лучше Cursor, не hard kill).
  • Англ. аббревиатуры: «CG Artist», «3D Artist» — для marketplace-графики могут быть undesirable, но не hard kill без prefs.

5.3 Blacklist (слой A) — расширить, но token-aware

Уже есть урок: водитель ⊂ руководитель. Только границы слова.

Hard drop для designer (без design-сигнала)
  • менеджер / manager / руководитель продаж
  • маркетолог / SMM / SEO-специалист
  • рекрутер / HR / бухгалтер / юрист
  • оператор call / колл-центр / курьер / водитель
  • врач / медсестра / преподаватель / учитель
  • логист / байер / закупк
  • разработчик / developer / golang / devops / QA engineer / ML-инженер
  • менеджер маркетплейс / менеджер WB/Ozon (без «дизайн»)
Не hard-drop (отдать Cursor)
  • «Дизайнер маркетплейсов»
  • «Графический дизайнер / менеджер макетов» (есть дизайн)
  • «Senior-дизайнер / Арт-директор»
  • «Дизайнер карточек товаров»
  • «Коммуникационный дизайнер»
  • «Digital Brand Designer»
  • UI/UX при undesirable — soft downrank, не kill (если вдруг нужен охват)

5.4 Правило «роль + исключение»

IF title matches MANAGERISH AND NOT title matches DESIGN_SIGNAL → hard reject
IF sphere known AND NOT title matches SPHERE_ALLOW → hard reject
ELSE pass to deep / Cursor

Именно связка «менеджер AND NOT дизайн» сохраняет «Менеджер дизайн-команды» / редкие гибриды, если в title есть сигнал. В прогоне таких почти не было; зато «Менеджер маркетплейсов» отсечётся честно.

6. Preferences, References, Portfolio

6.1 Разделить оси (концепт UI)

ReferencesVacancy ReferencesCursor calibration only

6.2 Что поправить в текущем дизайнерском конфиге (без кода)

  • Убрать из Desirable для SERP: Москва, гибрид, 115000, на руки, голый маркетплейс, Wildberries/Ozon как одиночные токены.
  • Оставить в Role desirable: дизайнер карточек, инфографика, графический дизайнер, Rich content, фирменный стиль, карточка товара.
  • Tools → Cursor: Figma, Photoshop, Illustrator, CorelDRAW.
  • Reject дописать короткими ролями: менеджер (с оговоркой через код), маркетолог, SMM, рекрутер, оператор, логист, разработчик, backend, QA, ML — плюс полагаться на allowlist, чтобы не ловить ложные срабатывания на длинных title.
  • Undesirable: UI/UX-only, 3D-only, motion-only — правильно как soft, не переносить в Reject, пока не уверены.

6.3 References

Одна архивная «дизайнер маркетплейсов» — слабо для калибровки. Нужно 3–5 живых FIT: карточки WB/Ozon, инфографика, статическая графика, возможно e-com арт-директор — с разными зарплатами/форматами. References не должны тащить поиск; только учить Cursor «как выглядит да».

6.4 Portfolio

Ссылка на Яндекс.Диск ок, но Cursor выигрывает от 2–4 якорных фраз в профиле (notes / sphere comment): «карточки товаров WB/Ozon», «инфографика», «Figma+PS+AI», «не чистый UI/UX приложений». Это дешевле, чем надеяться, что SDK прочитает диск.

7. Роль Cursor после ужесточения

Cursor должен отвечать на вопросы уровня:

  • Это дизайн карточек / коммуникации или соседний digital?
  • Грейд и вилка ЗП стыкуются?
  • Гибрид/офис терпим при prefs?
  • Слишком UI/UX / 3D / motion относительно резюме?

Cursor не должен отвечать на:

  • «Это врач?»
  • «Это менеджер продаж?»
  • «Это Python Tech Lead?»
После allowlist доля Cursor-вызовов на мусоре должна упасть на порядок. Тогда можно спокойно держать 3–5 воркеров и не упираться в 18 минут Clear Check.

Дополнительные дешёвые pre-Cursor эвристики

  • Если title allowlist ок, но snippet SERP содержит «входящие заявки», «холодные звонки» — soft penalty или hard reject.
  • Лимит deep_score_max: пока префильтр сырой — 40–60; после allowlist можно вернуть 80–100.
  • Не слать в Cursor дубликаты title+company в одном прогоне.

8. Риски ложных отказов и страховки

РискПримерСтраховка
Редкий title без «дизайн» «Художник компьютерной графики» Расширять allow-синонимы; лог «allow-miss» для ручного разбора
Англ. роль «Visual Designer», «CG Generalist» EN-aliases в allow; CG — серая зона → Cursor
Слишком жёсткий Reject «менеджер» «Менеджер дизайн-системы» Только «managerish AND NOT design-signal»
Name-only SERP режет охват роль только в description Адаптивный fallback: если < N карточек — включить description
Гибрид нужен, remote-only в URL хорошие МСК гибрид Отдельный флаг format в конфиге поиска
Режим «shadow filter»: первую неделю allowlist только логирует «оставили бы / убрали бы», но не режет. Сверка с фактом Cursor ≤20%. Если precision высокая — включать kill.

9. Roadmap внедрения (разумный порядок)

  1. Сегодня/завтра без кода: почистить Desirable (убрать гео/ЗП/голые МП-токены); дописать Reject короткими ролями; добавить 3–5 references; якоря в профиле.
  2. Быстрый код-win: allowlist title для известных sphere до deep; правило managerish AND NOT design; расширить designer blacklist (врач, оператор, логист…); Desirable SERP → name-only или отключаемый.
  3. SERP hygiene: разделение role-desirable vs tools; sync_hh только из role; опционально выключить dual-seed.
  4. Наблюдаемость: в лог писать reason code: serp, reject, sphere-allow-miss, sphere-blacklist, cursor. Иначе снова угадываем.
  5. Тонкая настройка: format flag, adaptive description, shadow mode, калибровка порога queue под дизайн (возможно 55–65, не 70 — смотреть по топу).
Порог 70 в прогоне оставил 1 вакансию при живых 54–64% дизайн-ролях. Возможно, для дизайна временно threshold 55–60 после очистки потока — иначе «хорошие» не доживают до очереди. Но снижать порог до очистки потока нельзя: получите менеджеров в очереди.

11. Открытые вопросы на завтра

  1. Насколько широкая сфера «Дизайнер»: только карточки/инфографика или ещё бренд/коммуникации/арт-дирекшн?
  2. Гибрид/Москва — must, nice, или вообще не фильтр поиска?
  3. UI/UX и 3D — жёсткий reject или только undesirable?
  4. Нужен ли второй seed Desirable вообще, если sphere seeds уже role-accurate?
  5. Готовы ли включить allowlist сразу в kill-режиме или сначала shadow-log неделю?
  6. Порог очереди 70 vs 55–60 после очистки потока.
Если коротко сформулировать продуктную цель одной фразой: «HH ищет роль, Python подтверждает роль по заголовку, Cursor оценивает совпадение с человеком.» Сейчас HH ищет слова, Python слабо возражает, Cursor оценивает всё подряд.
